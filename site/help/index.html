Автообновление прошивки

У Arduino Uno нет сети: прошивку на неё всегда записывает компьютер, к которому она подключена по USB. Здесь описано, как сделать, чтобы этот компьютер сам ставил новую версию, как только вы её опубликуете на сайте. Ручная прошивка тоже работает, см. ниже.

Агент автообновления поддерживает Arduino Uno и Nano (через avrdude с компьютера, к которому подключена плата) и Raspberry Pi Zero (агент работает на самой Pi и ставит программу её install.sh). Pico, ESP8266 и ESP32-CAM пока прошиваются вручную, инструкция – в архиве (FLASH.txt).

Как это работает

bhf.pp.ua                     компьютер у платы                 Arduino Uno
──────────                    ─────────────────                 ───────────
1. собрали прошивку
2. «Опубликовать на
   устройство» → версия N  ←── bhf-agent раз в минуту:
                              «есть новая версия?»
                              да → скачать zip, сверить sha256
                              → avrdude ───────── USB ─────────→ новая прошивка
                              ← прочитать Serial ←─────────────── «bhf … job <id>»
   статус «прошито» ←──────── отчёт
  • Устройство на сайте = одна плата: у него есть ID и секретный токен. Токен показывается один раз, на сервере хранится только его хеш.
  • Агент bhf-agent.py – один файл на Python, без зависимостей, кроме avrdude. Работает на Windows, macOS, Ubuntu/Debian и Raspberry Pi.
  • Агент ставит версию, только если её sha256 отличается от уже прошитой. После 3 неудачных попыток одной версии он ждёт следующую.
  • Загрузчик Uno при прошивке не стирается, так что «окирпичить» плату нельзя: если что-то пошло не так, просто прошейте ещё раз.
  • Опубликованная версия хранится, пока не опубликуете новую или не удалите устройство. Сборки без публикации удаляются через 7 дней.

Шаг 2. Агент на компьютере у платы

Команда once проверяет и прошивает один раз – так удобно проверить, что всё работает. Служба (run) делает то же раз в минуту и стартует сама после перезагрузки.

Windows 10/11 (PowerShell) 
# 1. Python и avrdude (один раз)
winget install -e --id Python.Python.3.12          # или python.org, галочка "Add python.exe to PATH"
mkdir C:\bhf; cd C:\bhf
Invoke-WebRequest https://github.com/avrdudes/avrdude/releases/download/v8.3/avrdude-v8.3-windows-x64.zip -OutFile avrdude.zip
Expand-Archive avrdude.zip -DestinationPath avrdude
Invoke-WebRequest https://bhf.pp.ua/bhf-agent.py -OutFile bhf-agent.py
py -m pip install pyserial                           # необязательно: проверка вывода платы после прошивки

# 2. настройка и проверка (порт: py bhf-agent.py ports)
py bhf-agent.py setup --device DEVICE_ID --token TOKEN --port COM3
py bhf-agent.py once

# 3. автозапуск при входе в Windows (без прав администратора)
Set-Content "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\bhf-agent.cmd" 'start "" pyw C:\bhf\bhf-agent.py --log C:\bhf\agent.log run'
Start-Process pyw -ArgumentList 'C:\bhf\bhf-agent.py','--log','C:\bhf\agent.log','run'
Get-Content C:\bhf\agent.log -Wait                   # журнал, Ctrl+C – выйти

# остановить / убрать
Get-Process pythonw | Stop-Process
Remove-Item "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\bhf-agent.cmd"

Права администратора не нужны. Нет COM-порта у клона с чипом CH340 – нужен драйвер CH340 (его установка требует прав администратора). Пока агент работает, порт занят: перед ручной прошивкой или монитором порта остановите его.

Ubuntu / Debian 
# 1. пакеты и доступ к порту (один раз, нужен sudo)
sudo apt install -y avrdude python3 python3-serial
sudo usermod -aG dialout $USER                       # потом выйти и войти (службе это не нужно)
mkdir -p ~/bhf && cd ~/bhf && curl -fsSLO https://bhf.pp.ua/bhf-agent.py

# 2. настройка и проверка
python3 bhf-agent.py setup --device DEVICE_ID --token TOKEN
python3 bhf-agent.py once

# 3. служба systemd (стартует при загрузке, перезапускается при сбое)
sudo tee /etc/systemd/system/bhf-agent.service >/dev/null <<EOF
[Unit]
Description=bhf firmware auto-update agent
After=network-online.target
Wants=network-online.target
[Service]
User=$USER
ExecStart=/usr/bin/python3 -u $HOME/bhf/bhf-agent.py --config $HOME/.config/bhf-agent/config.json run
Restart=always
RestartSec=30
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now bhf-agent
journalctl -u bhf-agent -f                           # журнал

# остановить / убрать
sudo systemctl disable --now bhf-agent

Порт пропадает сразу после подключения (клоны с CH340)? sudo apt remove brltty. «Permission denied» при once – вы ещё не в группе dialout: выйдите и войдите.

Raspberry Pi (Raspberry Pi OS) 
# 1. пакеты (пользователь Pi по умолчанию уже в группе dialout)
sudo apt update && sudo apt install -y avrdude python3-serial
mkdir -p ~/bhf && cd ~/bhf && curl -fsSLO https://bhf.pp.ua/bhf-agent.py

# 2. настройка и проверка (Uno обычно /dev/ttyACM0, клоны – /dev/ttyUSB0)
python3 bhf-agent.py ports
python3 bhf-agent.py setup --device DEVICE_ID --token TOKEN
python3 bhf-agent.py once

# 3. служба systemd
sudo tee /etc/systemd/system/bhf-agent.service >/dev/null <<EOF
[Unit]
Description=bhf firmware auto-update agent
After=network-online.target
Wants=network-online.target
[Service]
User=$USER
ExecStart=/usr/bin/python3 -u $HOME/bhf/bhf-agent.py --config $HOME/.config/bhf-agent/config.json run
Restart=always
RestartSec=30
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now bhf-agent
journalctl -u bhf-agent -f

Подходит любая Pi с USB (Zero 2 W через OTG-переходник, 3, 4, 5) и Raspberry Pi OS Lite без экрана, настройка по ssh. Uno питается от USB самой Pi. Пины GPIO не нужны: всё идёт по USB-кабелю.

Raspberry Pi Zero / Zero 2 W – агент на самой Pi 
# Устройство на шаге 1 – с платой «Raspberry Pi Zero». Raspberry Pi OS (Lite подходит), по ssh.
# Python уже есть, avrdude не нужен. Агент работает от root: ставит службу bhf-blink и управляет светодиодом.
sudo mkdir -p /opt/bhf-agent && cd /opt/bhf-agent
sudo curl -fsSLO https://bhf.pp.ua/bhf-agent.py
sudo python3 bhf-agent.py --config /etc/bhf-agent.json setup --device DEVICE_ID --token TOKEN
sudo python3 bhf-agent.py --config /etc/bhf-agent.json once      # ставит опубликованную версию

# служба: проверяет раз в минуту, стартует при загрузке
sudo tee /etc/systemd/system/bhf-agent.service >/dev/null <<EOF
[Unit]
Description=bhf firmware auto-update agent
After=network-online.target
Wants=network-online.target
[Service]
ExecStart=/usr/bin/python3 -u /opt/bhf-agent/bhf-agent.py --config /etc/bhf-agent.json run
Restart=always
RestartSec=30
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now bhf-agent
journalctl -u bhf-agent -f                # агент
journalctl -u bhf-blink -f                # сама «прошивка»: сообщение и blink N

# остановить агента (программа bhf-blink продолжит работать)
sudo systemctl disable --now bhf-agent
# убрать и программу: sudo systemctl disable --now bhf-blink

После установки агент проверяет, что служба bhf-blink запущена и в её журнале есть строка с ID задания, и отправляет отчёт на сайт. Ручной вариант без агента: скачать zip на главной, перенести на Pi и выполнить sudo sh install.sh (или sudo python3 bhf-agent.py flash файл.zip).

macOS 
# 1. avrdude и Python из Homebrew (https://brew.sh), sudo не нужен
brew install avrdude python
mkdir -p ~/bhf && cd ~/bhf && curl -fsSLO https://bhf.pp.ua/bhf-agent.py

# 2. настройка и проверка
python3 bhf-agent.py setup --device DEVICE_ID --token TOKEN
python3 bhf-agent.py once

# 3. автозапуск (launchd, при входе в систему)
cat > ~/Library/LaunchAgents/ua.pp.bhf.agent.plist <<EOF
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>ua.pp.bhf.agent</string>
  <key>ProgramArguments</key><array>
    <string>$(which python3)</string><string>-u</string><string>$HOME/bhf/bhf-agent.py</string><string>run</string>
  </array>
  <key>RunAtLoad</key><true/><key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string>$HOME/bhf/agent.log</string>
  <key>StandardErrorPath</key><string>$HOME/bhf/agent.log</string>
</dict></plist>
EOF
launchctl load ~/Library/LaunchAgents/ua.pp.bhf.agent.plist
tail -f ~/bhf/agent.log

# остановить / убрать
launchctl unload ~/Library/LaunchAgents/ua.pp.bhf.agent.plist

Python с python.org вместо Homebrew: один раз запустите «Install Certificates.command» из папки Python, иначе будет ошибка SSL.

Шаг 3. Опубликовать прошивку

  1. На главной соберите прошивку. Под кнопкой «Скачать» появится блок «Опубликовать на устройство», ID и токен там уже подставлены.
  2. Нажмите «Опубликовать». Номер версии устройства увеличится на 1.
  3. Агент заберёт новую версию в течение 1–2 минут: он проверяет раз в минуту, а сервер может отдавать старый статус до минуты. Нажмите «Обновить статус» выше, чтобы увидеть «прошито» и вывод платы.

Из командной строки (сборка с ID JOB_ID должна быть готова):

curl -s -X POST https://bhf.pp.ua/api/devices/DEVICE_ID/publish \
  -H "Authorization: Bearer TOKEN" -H "content-type: application/json" -d '{"job":"JOB_ID"}'
curl -s -H "Authorization: Bearer TOKEN" https://bhf.pp.ua/api/devices/DEVICE_ID     # версия и отчёт агента

Ручная прошивка (без агента)

Raspberry Pi Zero: см. FLASH.txt в архиве (scp + sudo sh install.sh). Arduino: скачайте zip на главной и распакуйте его. Команды выполняйте в распакованной папке, файл FIRMWARE.hex замените на свой .hex. Если агент запущен, сначала остановите его: порт может занимать только одна программа.

Windows (PowerShell) 
.\avrdude\avrdude.exe -c arduino -p m328p -P COM3 -b 115200 -U flash:w:FIRMWARE.hex:i
# вывод платы (UTF-8), Ctrl+C – выйти
[Console]::OutputEncoding = [Text.Encoding]::UTF8
$s = New-Object System.IO.Ports.SerialPort COM3,115200; $s.Encoding = [Text.Encoding]::UTF8; $s.DtrEnable = $true; $s.Open(); while ($true) { $s.ReadLine() }
Ubuntu / Debian и Raspberry Pi 
avrdude -c arduino -p m328p -P /dev/ttyACM0 -b 115200 -U flash:w:FIRMWARE.hex:i
screen -U /dev/ttyACM0 115200        # вывод; выход: Ctrl+A, K, Y  (sudo apt install screen)
macOS 
avrdude -c arduino -p m328p -P /dev/cu.usbmodem1101 -b 115200 -U flash:w:FIRMWARE.hex:i
screen -U /dev/cu.usbmodem1101 115200   # выход: Ctrl+A, K, Y

Агент умеет прошить и скачанный файл: он сам найдёт порт и при необходимости повторит на скорости 57600 для старых загрузчиков. Отчёт на сервер он при этом не отправляет.

python3 bhf-agent.py flash Downloads/arduino_uno-blink-1a2b3c4d.zip      # Windows: py bhf-agent.py flash ...

Если не работает

  • «no serial port found»: проверьте кабель (некоторые кабели только для зарядки), выполните bhf-agent.py ports, задайте порт явно: setup … --port COM3.
  • «not in sync» / «programmer is not responding»: порт занят (Arduino IDE, монитор порта, второй агент) или у клона старый загрузчик. Агент сам пробует скорость 57600.
  • «wrong token»: ID или токен неверны, или устройство удалено. Создайте новое и снова выполните setup.
  • «прошито, но Serial не показал job»: прошивка записана, но проверка вывода не прошла. Возможно, порт перехватила другая программа или на Windows не установлен pyserial.
  • Состояние агента: bhf-agent.py status. Подробный журнал: -v. Конфиг с токеном (права только для владельца): Windows %APPDATA%\bhf-agent\config.json, остальные ~/.config/bhf-agent/config.json.
